# Автономное управление спутниковой группировкой

КосмоХакатон 2026, трек «Автономное управление спутниковой группировкой».

Веб-сервис для оператора наземной смены: распределяет задания между спутниками с учётом энергии, температуры, калибровки и наземной связи, перестраивает план при новых сообщениях (срочные заявки, отказы аппаратов, отмена сеансов связи) и сравнивает варианты продолжения смены.

> Статус: каркас репозитория. Планировщик и веб-сервис в разработке.

## Структура репозитория

| Папка / файл | Назначение |
|---|---|
| `model/` | Расчётная библиотека организаторов (`resource_env.py`, `operations.py`). Не изменяем. |
| `data/` | Сценарии P01–P04 от организаторов. |
| `examples/` | Пример последовательности сообщений (`events_demo.json`). |
| `planner/` | Наш планировщик (в разработке). |
| `app/` | Веб-сервис и интерфейс оператора (в разработке). |
| `tests/` | Тесты. |
| `results/` | Сохранённые расчёты (JSON-выгрузки для повторения). |
| `docs/` | Материалы хакатона: постановка, критерии, описание данных. |

## Запуск

Требуется Python 3.10+. Библиотека организаторов не имеет сторонних зависимостей.

```bash
git clone https://github.com/Grafitiks/Kosmohack_sputniki.git
cd Kosmohack_sputniki
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest                 # проверка, что комплект подключён
```

Воспроизведение сохранённого расчёта:

```bash
python model/operations.py --result results/<файл>.json --output replay.json
```

## Правила работы в команде

- Ветка `main` всегда рабочая. Новое делаем в отдельных ветках и вливаем через pull request.
- Не коммитим пароли, ключи и личные пути к файлам.
- Файлы в `model/` и `data/` не правим: это условия задачи.

## Метод, настройки, эксперименты

Будет заполнено по мере разработки: описание алгоритма, параметры, сравнение с простым правилом (ближайший срок / приоритет / ценность), результаты на P01–P04 и на сценариях с событиями.
