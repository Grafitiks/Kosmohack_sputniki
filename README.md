# Kosmohack_sputniki

Проект для КосмоХакатона 2026, трек «Автономное управление спутниковой группировкой».

Делаем веб-сервис для оператора смены. Он раздаёт задания спутникам (передача данных на Землю, ретрансляция), следит за зарядом, температурой и калибровкой, пересчитывает план, когда приходят новые заявки, отказы или отмена сеансов связи, и сравнивает два варианта продолжения смены.

Пока в репозитории только заготовка: файлы организаторов и пустые папки под наш код.

## Что где лежит

- `model/` - расчётная библиотека организаторов (`resource_env.py`, `operations.py`), её не трогаем
- `data/` - сценарии P01-P04
- `examples/` - пример событий во время смены
- `planner/` - планировщик (пока пусто)
- `app/` - веб-сервис (пока пусто)
- `tests/` - тесты
- `results/` - сохранённые расчёты
- `docs/` - постановка, критерии оценки и описание данных

## Запуск

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/Grafitiks/Kosmohack_sputniki.git
cd Kosmohack_sputniki
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python3 -m pytest
```

Повторить сохранённый расчёт:

```bash
python3 model/operations.py --result results/файл.json --output replay.json
```

## Запуск в контейнере

Есть `Dockerfile` — сессии сервис держит в памяти, ничего на диск не пишет и не читает localhost, так что образ можно катить на любой хостинг как есть.

```bash
docker build -t kosmohack-sputniki .
docker run -p 8000:8000 kosmohack-sputniki
```

Порт слушает `$PORT`, если хостинг его задаёт (иначе 8000 по умолчанию).

## Метод и эксперименты

Полные результаты прогонов (с trace) в репозитории не лежат — они тяжёлые, по несколько десятков мегабайт на сценарий. Получить их можно командой `python3 planner/run_compare.py --save-runs` (лягут в `results/runs/`), а что расчёт повторяется — проверить через `python3 model/operations.py --result results/runs/файл.json --output replay.json`.
